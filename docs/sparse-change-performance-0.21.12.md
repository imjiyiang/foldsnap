# 0.21.12 少量变化、大量未变化文件的备份检查

本轮全部数据由 Go 测试在独立临时目录中生成。没有连接安装应用的 API/生产 SQLite，也没有运行或修改个人计划、源目录及备份仓库。实际测试使用本机临时目录所在文件系统，不能把耗时外推为外置机械盘速度。测试退出后临时源、仓库和恢复输出由测试框架清理，报告保留于项目 `.data/`。

## 改动与安全边界

旧版直接复用候选历史文件时先完整读内容，而发布前 `Verify` 会通过新的硬链接再读一次同一 inode；增量/镜像还会在私有暂存写入之前先审计完整历史基线。现在把候选的内容校验统一到发布前必经的暂存 SHA-256 校验中。源内容仍独立完整读取；增量/镜像完整基线审计继续执行；候选的类型、大小、权限、mtime、扩展属性检查及链接后的物理身份核对保留。未变化备份文件的完整内容读取由快照 2 次减至 1 次，增量/镜像 3 次减至 2 次。

不缓存跨运行或跨写入阶段的哈希结果，不跳过最后的暂存读取。相同长度、恢复 mtime 的内容篡改，候选替换为符号链接，以及发布前内容/权限改变必须失败。快照模式中，同尺寸/元数据的历史损坏候选现在会在最终验证时明确失败，而非此前在候选筛选时跳过它、重新传输源文件；诊断失败不会发布新恢复点。失败暂存保留为诊断/安全恢复素材，不能当成成功快照。

首次备份仍在仓库初始化之前完成完整 rsync 预演。后续新一代在恢复暂存/链接决定后生成唯一的实际待传输清单，rsync 新鲜预演与真实传输共用这个清单。已直接复用/安全恢复的文件从两者中排除，链接不支持而回退传输的文件仍在清单里。私有暂存可在预演失败时存在，但不会发布快照或推进 current。没有实际 rsync 传输时不做空预演；新一代的全部最终布局、内容、元数据、目标身份、fsync 和原子发布保持不变。

稀疏预演只创建必要的临时父目录，并对同一父目录去重。移除项/保留项、源和目标身份及重叠检查继续由 Go 的完整计划/选择/视图检查处理。rsync 不获得任何复用文件的路径，也不使用历史 link-dest。

## 独立负载与计量

每种模式重新创建 10,000 个 8 KiB 小文件和 3 个 8 MiB 大文件；先完成首次备份，再修改 5 个、改名 5 个、删除 3 个、新增 3 个小文件，执行第二次备份。增量保留消失的旧路径，镜像在测试计划内明确授权这些模拟删除；不执行历史保留清理。

内容读取通过 Go HashFile 的真实开始事件逐文件计数，成功完整读取量由固定夹具文件大小换算，不把 rsync 的进度 Bytes 事件算成 SHA-256 读取。旧版最初的字节采样混入了 65,536 B rsync 进度；原始值保存在 `.raw.json`/`goHashBytesRawTelemetry`，正式对比采用真实完整文件读取次数乘确定大小，目标副本读取计数未受影响。

Execute 计时包含新鲜预演、候选处理、真实传输、最终校验、持久化与提交；不包含此前扫描和之后审计/恢复。内容统计不包含 rsync 内部读取、元数据读取、文件系统物理 IO，也不代表整盘读写量。系统缓存没有清除，单次耗时仅作本机观测，不能据此承诺固定比例。

计时后完整审计前后两个恢复点，验证未变化大文件确实共享历史 inode；恢复完整新版本，再恢复旧版本的修改前文件，核对新增/修改/保留/移除内容。全部输出仍在临时目录中。

## 回归

- 三种模式：每个未变化源文件恰好一次独立内容读取，最后的目标暂存恰好一次完整读取；额外历史读取仅为同步模式保留的初始基线审计。
- 历史同长篡改并恢复 mtime、源同长篡改、源校验时历史篡改、候选被符号链接替换、发布前内容/权限变更、取消：均不得发布新一代或推进 current。
- 真实 rsync 包装器验证新鲜预演和真实传输清单逐字节一致，只包含实际变化项，嵌套父目录可用，复用文件不进入任意清单，无 link-dest。
- 预演失败：不执行传输，不发布新历史，应用不改变历史内容。
- 既有历史不可变、三模式、批准单次使用、恢复、索引和取消回归继续运行。

## 本机独立负载结果

| 模式 | 0.21.11 Execute | 0.21.12 Execute | 未变化备份文件完整读取 |
| --- | ---: | ---: | --- |
| snapshot | 6.882 s | 5.343 s | 2 -> 1 次 |
| incremental | 7.833 s | 5.713 s | 3 -> 2 次 |
| mirror | 7.606 s | 5.765 s | 3 -> 2 次 |

每种模式减少 107,020,288 B 的 Go 逻辑 SHA-256 内容读取，源文件独立读取保持一次；这些数字不是物理磁盘节省量。三种模式的实际待传输项均为 8 个，其他 9,995 个文件通过历史候选复用；恢复过程验证了增量保留旧路径、快照/镜像移除当前视图旧路径以及历史版本仍可恢复。新恢复点仍需要完整命名空间、硬链接、目录元数据和持久化，因此少量变化时不承诺零写入。

重试路径也已检查：预演失败留下的私有暂存不应让下次把大量历史可复用文件当作可变暂存再读/克隆/复制。现在先选择已提交历史，再只从中断暂存恢复剩余项；回归验证不读取旧暂存候选、结果与历史仍共享 inode。不能从历史复用的恢复项仍需独立源/暂存检查并克隆或复制，不能硬链接可变中断文件进新恢复点。

回归日志：`.data/sparse-0.21.12-tests.log`、`.data/sparse-0.21.12-vet.log`；独立负载前后原始 JSON 分别在 `.data/sparse-before-0.21.11/`、`.data/sparse-after-0.21.12/`，中间仅合并哈希的结果保存在 `.data/sparse-after-hash-consolidation-0.21.12/`。汇总：`.data/sparse-0.21.12-acceptance.json`。复现命令：`LOCALBACKUP_SPARSE_REPORT="$PWD/.data/sparse-recheck" go test ./internal/backup -run '^TestSparseChangePerformanceWorkload$' -count=1 -v`。

独立 0.21.12 原生应用包位于 `.data/sparse-optimization-0.21.12/LocalBackup.app` 和同目录 zip。独立负载测试阶段没有替换或启动用户当时的 0.21.11 应用；后续用户授权的本机安装验收见下文。全部独立临时测试数据随测试清理，安装应用没有新增测试计划。
