# 中断暂存文件恢复（0.14.0）

服务意外退出后，原运行继续标记为“运行中断”，不把未完成目录当成恢复点。重新预览并运行同一配置的备份时，会检查目标仓库中兼容的暂存工作，恢复已传完且验证通过的普通文件。原运行审计记录保留，新运行独立记录恢复数量和字节数。

每份新暂存工作在传输前原子持久化 `<snapshotId>.resume.json`，并同步其父目录。标记位于 staging 根下，不进入最终快照；包含协议版本、暂存 ID、创建时间和配置绑定摘要。摘要覆盖计划/模式、源身份与规则、目标身份、仓库 ID、服务数据排除路径和元数据模式。标记只是查找候选的提示，不是可信清单：即使标记被伪造，也不能跳过任何内容验证。

恢复仅从同仓库同计划的目录中选取最多 8 份兼容候选，依次检查新扫描清单中已启用源的普通文件。路径必须安全、没有符号链接；大小、权限、时间、SHA-256 和启用的扩展属性必须匹配，还会重新读取当前源文件，验证其实际内容与元数据。候选不完整、损坏、源已变化、绑定或配置不匹配时，照常传输。旧暂存中的其他文件与临时片段不会被导入。

恢复到全新的 staging 目录。macOS 优先 clonefile，其他文件系统回退到带取消检查的独立复制，绝不把仍可修改的中断文件硬链接进新恢复点。克隆/复制后的文件仍参加完整目标 SHA-256、结构和元数据校验；所有源身份与目标基线检查、镜像删除审批、fsync 和原子发布要求均保留。旧暂存不会被自动修改或删除。

这实现的是跨服务重启的**完整文件级恢复**。传输到一半的大文件仍从头传输；不会沿用过期预览审批，不会自动将中断运行当作成功，也不会在应用启动时绕过计划策略强制续跑。块级/单文件中途续传、旧暂存的显式检查清理界面及真正断电/硬盘拔插验证仍待完成。

验收包括真实进程 SIGKILL：第一源文件传输完成，第二源文件正在传输时结束服务；重启后原运行标记中断，新运行恢复第一文件并重新传输第二文件，发布后的全部文件再次校验。修改旧暂存文件后，新恢复点保持完整。另覆盖损坏/不完整候选、源内容变化、规则变化、无效标记、符号链接候选与恢复中取消。

第二组实机进程验收没有结束服务遗留的 rsync 子进程：确认其进程组仍存活后立即重启服务并创建新运行。两者使用不同暂存目录，新恢复点仍通过全部内容校验及旧暂存修改隔离检查。该结果证明此场景中的目录隔离，不代表已经完成所有断电/拔盘和主动并发改写故障矩阵。
