# 源目录身份与重新绑定（0.10.0）

保存计划时，后端记录每个源目录的卷 UUID、目录文件 ID、目录创建时间、挂载根和卷内相对路径。目录 ID 与纳秒级创建时间使用 JSON 字符串，避免浏览器 Number 精度损失。目录 ctime 不作为身份：正常修改内容或改名都会改变 ctime。

## 使用和迁移

- 新计划保存时自动绑定当前选择的目录，编辑页显示卷 UUID、目录 ID 和核对状态。
- 0.9 及更旧的计划没有源根身份。升级后需要打开计划、确认当前源路径并保存一次，才会建立首次绑定。预览和运行会明确提示未绑定；不会在后台把一个同名目录自动当作原源。首次绑定只能确认当前所选目录，不能补证过去没有记录的根身份。
- 目录改名或移动后，点击源路径重新选择原目录再保存。只有卷 UUID、目录 ID 和创建时间均匹配才沿用原 source ID 与历史。选择的是另一个目录时，移除旧源并作为新源添加，产生独立存储 ID。
- 同一路径被新目录、普通文件或符号链接替代时，不会继续扫描为原目录，也不会让镜像把旧文件当成全部删除。
- 外置源盘换挂载名称时，按原卷 UUID、卷内相对路径和目录身份重新定位；不会按磁盘名或相似目录名猜测。目录自身改名仍需手动重新选择，不进行全盘搜索。
- 已绑定源离线时，允许保留相同绑定并修改规则、开关等配置。新增或修改为一个不存在的源路径仍会拒绝；启用一个已被其他目录替代的源也会拒绝。客户端清空或伪造身份字段不能改变已有 source ID 的绑定。

## 运行与恢复

执行前、扫描前后、传输前和发布前重新核对源身份。重新定位后再次检查源之间、源与本计划及其他计划目标之间的重叠。所有扫描和复制继续不跟随符号链接。

源目录暂不可用或出现不同 UUID 的磁盘时，任务进入 `waiting_for_source`，保留历史，30 秒后重新检查原身份。运行记录与队列的重试状态在同一事务中保存，重启后仍等待；可暂停、继续或取消。源原样返回后继续本次任务的重新扫描。若源在已经传输时断开，当前任务可能失败，未验证 staging 不发布；这不等于跨进程 staging 续传。

同卷同路径的目录 ID/创建时间变化，或未建立首次绑定，进入需要确认状态。身份检查失败不能作为空目录继续发布。显式重新绑定使旧队列的完整配置审批失效，需要重新预览；原挂载名称自动变化只影响本次运行副本，不改写保存的计划。已经批准的预览若因重新定位而失效，仍需重新预览。

当前完整计划会等待其任一启用源恢复；不会在后台悄悄跳过离线源并报告整计划成功。可以通过 0.9 的手动目录范围功能仅备份在线源，其他源沿用上一份恢复点。自动按源拆分等待任务及更细的源状态仍未完成。

## 验证与边界

自动测试覆盖原目录改名后保留 ID/历史、同名替换拒绝、清空或伪造绑定拒绝、错误卷 UUID/创建时间拒绝、源根符号链接拒绝、替代挂载根候选按 UUID+目录身份定位、目录离线等待/重启/暂停/恢复、等待记录的事务回滚、跨计划重叠防护及旧计划显式首次保存。

目录身份的可靠性取决于文件系统是否提供稳定 ID 与创建时间。主要目标是 macOS APFS。Linux 后备设备标识不是跨重启的真实卷 UUID；没有稳定标识的文件系统不能声称等同 APFS 的身份保证。复制或重建目录通常产生新身份，即便内容相同，也不能冒充原目录。克隆出相同卷 UUID、目录 ID 与创建时间的整卷不在当前去重保证内，不应同时使用。

未连接实际测试外置源盘；挂载改名用可控候选目录测试，不能替代真实硬件拔插、休眠、异常断电验收。

本地界面验收使用独立生成的 `.demo/queue-live-b`：暂时改名后任务进入 waiting_for_source 且历史数量不变；原目录恢复后任务成功。随后从编辑页目录选择器重新选择改名后的原目录并保存，原 source ID、目录 ID、创建时间字符串全部保留；再次备份成功，新 manifest 携带相同绑定。验收后目录与计划路径恢复原值，所有示例自动计划保持暂停。证明记录在 `.data/source-binding-acceptance.json`；截图 `.data/source-binding-waiting.png`、`.data/source-binding-rebound.png`。完整 Go race 回归、无 cgo 专项回归、前端构建/格式及应用签名检查通过。
