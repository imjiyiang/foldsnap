# 受保护目录扫描阻塞调查

此文保留可复用的技术结论；个人文件名、本机绝对路径、实际计划标识和详细系统采样保留在不发布的本机诊断资料中。

## 现象与边界

备份工具曾正常扫描和执行，随后受保护的桌面、下载等目录在 open/目录枚举阶段阻塞，文件数、哈希字节数均为零。普通临时目录仍能立即枚举。Finder 的行为与后台服务不同，不能据此认定应用内的算法退化。

旧版和新版后端在相同终端启动方式、独立配置、禁用自动任务的条件下都无法枚举受保护目录。该结果说明当前系统访问链路存在问题；不能仅凭构建时间断言哪个版本引入故障，也不能把终端启动的权限环境等同于原生应用过去的权限环境。

## 证据与恢复

macOS 内核日志出现文件服务授权的 `watchdog expired for approval entry`，涉及 `kTCCServiceSystemPolicyDesktopFolder` 和 `kTCCServiceSystemPolicyDownloadsFolder`。同时其他应用也出现授权 watchdog 超时，支持系统授权环节阻塞；不等于已证明某个守护进程整体死锁。

Ad hoc 签名更新会改变代码要求，可能重新请求桌面和可移动宗卷权限；“等待系统授权”和此前的长期系统访问阻塞需要分别诊断。不能自行重置 TCC、关闭安全组件、终止系统服务或改变用户授权来掩盖问题。

本机问题在用户自主重启系统后恢复。后续应用更新遇到的正常系统授权请求，经用户允许后可继续访问。这些是单机观察，不代表所有目录阻塞都需要重启。

## 软件侧保护

- 单次目录读取有 30 秒截止时间，取消后不再发起新的系统读取。
- 最多四个未完成 OS 调用；同一路径的挂起请求合并，重试不会反复消耗槽位。
- 挂起调用真正返回后移除记录；后续任务重新读取，不复用已取消任务的迟到结果。
- 目录选择器与扫描共用有界目录读取，等待容量超时和实际读取超时有不同提示。
- 前后端版本不一致时提示刷新，避免旧浏览器界面掩盖新版行为。

这些保护限制故障影响，不会强制中断卡在内核中的 open，也不能代替系统授权恢复。注入阻塞回归覆盖合并、取消、容量上限、恢复后重读、遍历顺序与不跟随符号链接。
