# 智能调度阈值、最长检查与失败重试（0.11.0）

保存计划 → 调度与保留，可配置静默等待、最少变化文件路径、最小逻辑变化大小、变化触发的最短间隔、最长检查间隔，以及自动任务最多尝试次数。页面显示已保存计划最近的实际变化统计、等待原因、完整检查时间与重试资格时间；未检查时不会显示虚构的零。

## 变化触发

必须同时满足：启用文件变化触发、最近事件已静默足够时间、实际变化达到所有启用阈值、距上次整计划成功达到最短间隔。

数量/大小来自当前选择规则生成的目标视图与各目标基线的实际比较，不使用事件条数。相同 source/path 在多个目标上有变化只计一次；重命名的旧、新路径分别计数。普通文件及链接路径计入数量，纯目录结构变化不计入文件数；两个阈值均关闭时，目录结构变化也可触发。

每个变化路径大小取新旧非目录逻辑大小的较大值，跨目标取较大值再求和。它包含删除、缩小和仅元数据变化涉及的文件大小，不是 rsync 传输量，也不是物理磁盘 I/O。镜像/增量的排除保护和旧路径保留先应用，再计算差异。增量模式仅删除一个仍被保留的旧路径，不构成目标视图变化。

0 表示关闭数量或大小阈值，启用的两项需要同时达到。低于阈值时保留未处理事件和变化状态，后续继续累计净变化；重复事件不会虚增计数。文件改回原状后不计入净变化。下限以下且内容/事件版本未变化时，不会每两秒反复读取全部内容；仍会执行必要的轮询提示和每小时完整审计。变化状态持久化，服务重启不丢弃待累积变化。

最短间隔只约束变化触发。固定频率、手动及磁盘连接触发独立。单目录或部分目标的成功不冒充整计划成功，不能推迟整计划的间隔时钟。

## 最长检查间隔

0 关闭。正值表示从最近一次整计划成功或最近一次最长间隔检查起，达到该分钟数后执行完整源内容读取，绕过指纹复用。第一次没有成功历史时，以计划创建时间（缺失则首次观察时间）为起点。

没有实际变化时只记录检查，不生成空恢复点；有变化时绕过数量、大小、最短间隔及静默等待，创建 `max_interval` 任务。最终扫描、文件校验和镜像删除确认照常执行。若队列暂时无法接收，已检查的兜底任务保持待入队状态，保存新策略可取消旧兜底状态。

这是检查/补偿策略，不承诺休眠、磁盘离线或任务排队时准点完成。唤醒或目标重新可用后重新评估。最长间隔不能短于所设的变化最短间隔。

## 自动失败重试

最多尝试 1—10 次，包含首次执行。仅实际失败的自动任务建立失败重试，退避为 1、2、4、8…分钟，上限 60 分钟。失败次数、下一次资格和目标范围持久化；重启保留退避。磁盘连接任务重试仍只执行其原有目标，不能扩展到另一块轮换盘。

等待源/目标卷的任务不是失败，不消耗尝试次数。需要确认的任务等待人工处理，所有模式都禁止自动确认循环。手动失败不作为自动重试；取消结束本次任务，不作为失败重试，但启用的计划仍可按后续规则再触发，取消后至少冷却一分钟。暂停计划才会停止后续触发。

成功、保存修正后的源/调度配置可清除旧失败轮次。新的目标连接作为独立连接触发，可重新开始一轮。达到失败次数上限后不会绕过上限按每次轮询重新制造任务。运行详情记录 automaticAttempt/retryOf 以供审计。

## 兼容与默认值

旧计划缺失阈值时数量/大小关闭，缺失 minIntervalMinutes 保持原有 1 分钟；显式 0 关闭最短间隔。缺失最长间隔为关闭，缺失最多尝试次数为 3。新建计划使用变化数 10、最短 60 分钟、最长 1440 分钟、最多尝试 3 次，并默认启用变化与磁盘连接触发。固定频率仍使用独立的 intervalMinutes；尚未提供日历时刻/时区规则及每个目标独立策略。

配置范围限制：间隔至多一年，静默时间 0（默认 120 秒）或 10—86400 秒，路径阈值至多 100 万，逻辑大小至多 1 PiB。所有 API 保存路径（含离线修改调度的快速路径）均验证。

## 验证

自动测试覆盖跨目标去重、删除/缩小逻辑大小、未达阈值累积及保留事件、闲置统计不反复完整扫描、最短间隔、最长检查强制读取与无变化不备份、最大间隔单独启用时不提前扫描、离线保存验证、真正失败后运行第 2/3 次并停止、轮换目标重试范围、重启保留退避、手动失败不重试及确认循环阻止。

本地真实监听验收使用隔离生成的 `.demo/queue-live-b`：界面保存 2 个路径且 1 MiB、静默 10 秒、最短间隔显式 0 的策略。1 个变化路径/63 B 未创建任务；2 个路径/98 B 仍未创建任务；增大生成文件至 1 MiB 后，原生事件触发第 1 次自动 change 任务，成功生成恢复点并逐文件验证 2 个 SHA-256。验收后恢复原始示例文件、移除本次生成文件、恢复原调度并暂停全部示例计划，再手动备份确认恢复后的数据。证据在 `.data/schedule-acceptance.json`，界面截图 `.data/smart-schedule-thresholds.png`、`.data/smart-schedule-waiting.png`、`.data/smart-schedule-success.png`。完整 Go race 回归及更新后的原生闲置专项、无 cgo 策略专项、前端构建/格式和应用签名检查均通过。
