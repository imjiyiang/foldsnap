# 单目录与部分目录备份（0.9.0）

原设计允许同一计划整体运行或单独执行其中目录。现在可以点击计划卡片中的目录标签，直接预览该目录；也可以打开更多操作 →「选择目录备份」，勾选若干启用目录后预览。

## 恢复点语义

- 仅扫描与传输所选目录。其他源暂时未连接，不影响本次扫描。
- 针对每个目标，以其最新已完成恢复点为基线，更新所选目录并沿用其他目录的旧内容，最终发布经过完整验证的新恢复点。
- 尚未有任何备份的未选目录不出现在恢复点中。界面明确提示这一点；不会把空目录伪装成已经备份的数据。
- 快照模式中，所选目录消失的文件不进入新恢复点；其他未选目录原样保留。增量模式继续保留所选目录消失的路径。镜像模式只移除所选目录中已预览且明确确认的路径；其他目录受保护。所有历史版本均不变。
- 未选目录沿用的是各目标上次备份，不是其当前源状态。新恢复点不表示所有目录在同一时刻重新备份。
- 沿用的目标内容也要验证。损坏或丢失旧文件会阻止发布新恢复点；不会因为源未选择就跳过目标完整性校验。
- 计划中的启用开关和规则不改变。后续完整运行恢复处理全部启用目录。

## 审批与队列

请求使用稳定 sourceIds。后端按保存计划顺序规范化，所有配置源均启用时，选择全部目录等价于整计划；若含停用源，显式选择所有启用源仍保留停用源旧版本。无效、重复、其他计划或停用目录 ID 拒绝。

预览保存明确的目录范围，执行请求必须匹配。范围还通过所选源配置、完整视图及基线指纹绑定。排队保存完整计划，执行前比较全部配置（包括未选择的源），再在本次执行副本中应用目录选择。

同一计划的相同目录和目标范围合并重复请求。A、B 和完整计划可分别排队，串行执行。没有审批的自动重扫任务在执行时使用最新基线；已有审批的任务若因前一个任务改变基线，必须重新预览。排队/暂停状态及目录范围在重启后保留，已运行中断的任务仍按现有机制标为可恢复，不声称跨进程续传。

运行记录保留 sourceIds/sourceNames，快照 manifest 保留 updatedSourceIds；历史页面显示本次更新的目录。恢复仍可选择新恢复点内任意实际存在的文件（含沿用的旧目录）。

单目录成功只更新所选源的成功文件投影，不清除整计划的变更事件，也不作为整计划定时间隔的新成功基准。下一次自动检查仍会检查其他源的未处理变化。原生事件量可能保留到下次整计划检查；这样无需推断哪些合并事件只影响所选目录。

## 验证

真实 rsync 自动测试覆盖三模式的新旧目录组合、未选源离线、首次仅选部分源、镜像删除范围和确认、旧内容损坏阻止发布、不同范围分别入队及重复请求合并、重启串行执行后保留前一任务结果、审批范围不匹配、完整配置变更使排队任务失效、manifest 范围信息，以及后续整计划运行恢复全部目录。

本地界面验收：在独立生成的「筛选验收 · 照片与项目」计划中只选择「项目文档」，扫描 106 个所选文件，沿用「照片资料」的 3 个文件（另含目录记录），生成新恢复点。再次逐项检查 manifest 与实际 SHA-256，共验证 109 个文件，未选目录记录与原恢复点完全一致。运行及快照 ID 记录在 `.data/source-scope-acceptance.json`；界面截图为 `.data/source-scope-selection.png`、`.data/source-scope-preview.png` 和 `.data/source-scope-success.png`。所有示例计划继续暂停，未读取或修改个人资料。
