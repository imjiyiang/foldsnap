# Native change detection (0.2)

On macOS builds with cgo, `internal/adapters/fsevents` wraps Apple's FSEvents through pinned `github.com/fsnotify/fsevents` v0.2.0. Sources with file-change scheduling share a host stream with FileEvents, WatchRoot and NoDefer. Identical source paths are watched once even when referenced by multiple plans. Plan changes rebuild the stream and force reconciliation. No source stream recursively subscribes to every file under /Volumes: mount directory changes use a separate nonrecursive kqueue vnode notification, with periodic volume identity checks as a backstop.

Schema migration 002 adds watch_cursors and change_events. Each batch updates its host journal cursor and coalesced dirty paths atomically. Replacing a dirty-path row creates a new monotonic revision. Runs capture the pending revision before scanning and acknowledge only revisions no newer than that baseline after success. Changes received during backup therefore remain pending for the next run. Ignored paths obey the same first-match rules and ancestor-subtree pruning as the scanner. The live service data directory (database, WAL, access token) is always excluded from scanning and event selection, including when its parent is selected as a source.

The scheduler waits for the configured quiet period before reconciling dirty events. No directory walk happens while native streams are healthy, unchanged and not due for audit. Healthy native APFS scans can update only dirty subtrees from authenticated source projections (see [subtree scanning](subtree-scanning.md)); actual backups still use full selected manifests and complete target SHA-256 verification. A selected native event is compared against content history to avoid creating duplicate snapshots from delayed/coalesced notifications. This comparison includes extended-attribute fingerprints and detects changes hidden by same-size/same-mtime metadata.

Startup, changed watch configuration, MustScanSubDirs, dropped kernel/user events, root changes, mounts/unmounts and wrapped IDs require full reconciliation. A full content comparison is used, rather than trusting a cheap size/mtime signature. An hourly full audit covers advisory journal limitations and missed offline changes. Unavailable/unreadable roots never cause deletion of historical snapshots. A failed event transaction does not advance the persisted cursor; the service falls back to polling and retries native stream setup. A cursor newer than the current host event counter is discarded and reconciled.

For builds without cgo or platforms without native FSEvents, metadata polling remains supported. Such fallback cannot detect a same-size/same-mtime content change immediately, and automatic fallback comparisons force source content reads; explicit scans on supported APFS may reuse individually metadata-validated fingerprints. The API and Settings expose backend, health, root count, pending paths, durable cursor and listener errors.

Sources: [Apple FSEvents programming guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html), [fsnotify/fsevents](https://github.com/fsnotify/fsevents). These APIs are advisory; complete snapshots and content verification remain the correctness boundary.
