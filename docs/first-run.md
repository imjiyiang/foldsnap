# 首次备份引导（0.12.0）

概览和其他页面的「首次备份引导」提供环境检查、目录/磁盘检查、预览与首次恢复点三个步骤。没有恢复点时，概览突出显示开始设置入口；随时可以重新打开引导检查已保存计划。

- 引擎、数据库、运行平台来自实际服务检查。系统 openrsync 使用基础元数据模式时明确显示其范围，完整扩展属性仍需要 rsync 3.x。
- 源检查确认保存的卷/目录身份，并用不跟随源根链接的只读目录打开检查枚举权限；不会读取文件内容。
- 目标检查按保存的卷 UUID 找到原目录，做写权限预检查。不会创建测试文件，也不自动执行备份或修改绑定。
- 权限预检查并不代替真实预览、传输和最终校验。若 macOS 拒绝所选目录访问，需在系统设置的隐私与安全性中检查应用文件权限，再手动重新检查；工具不会自动授予系统权限。
- 所有界面新建计划默认暂停自动触发，默认仍采用快照模式。保存暂停的新计划后打开真实预览，用户点击开始才生成恢复点。用户若自行在调度页启用自动触发，保存后会遵循其选择。
- 已有计划的启用状态不会被引导改变。可以选择计划，查看源/目标问题、进入编辑、重新预览或浏览历史。
- 没有计划但存在导入历史时，也能进入全部历史与恢复，不将历史记录误报为没有备份。

`GET system/setup` 为经过身份验证的只读检查入口，不启动任务、不改变索引或调度。目标写权限只是预检查，不是对 ACL、只读驱动、空间和后续访问永久有效的承诺。

自动检查本身不安装 launchd，不更改系统权限，不下载引擎。无终端安装、升级、Developer ID/公证、完整元数据恢复、真实硬件故障测试等仍是剩余交付项。

本地验收使用独立空数据目录和 8788 端口，完整走通引导 → 创建计划 → 选择独立生成的源/目标 → 保存。真实 API 确认保存后 enabled=false、运行/快照/队列均为空；点击预览的开始后才生成首份经 SHA-256 校验的恢复点。验收服务已停止，现有主服务仍为原 7 个暂停计划。证明 `.data/onboarding-acceptance.json`，截图 `.data/onboarding-welcome.png`、`.data/onboarding-first-preview.png`、`.data/onboarding-success.png`。
