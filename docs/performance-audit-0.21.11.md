# 0.21.11 整体性能与磁盘工作量复查

目标：减少重复工作、内容/元数据读取和磁盘写入，同时保留完整安全边界。检查范围包括预览、后台变化检测、正式运行、零变更验证、有变更时直接复用/rsync/暂存验证、数据库目录记录与任务进度、持久化发布、列表及监控轮询。

## 本轮改动

- `file_entries` 过去在每次成功运行后删除所有启用源的记录并逐条插回，即使实际备份零变更。现在在一个事务中读取各启用源的现有目录记录，比较规范 JSON，只插入/更新差异并删除消失项；未参与的源保持原值，空选择仍删除该源旧项。无变化时 SQL 行修改和这部分 WAL 写入均为零。它是目录记录，不是 HMAC 指纹缓存，不能替代内容校验；成功后仍确认变化修订并持久化任务审计。
- 零变更校验中，相同阶段的路径/仓库身份检查和完整清单比较合并使用一次读取、解码的结果，内容审计复用该阶段已经验证的根路径。结束时重新读取清单并做完整比较。Execute 零变更分支的清单读取从 5 次减到 3 次（进入执行检查 1 次、完整校验开始 1 次、结束 1 次）；执行前的新鲜预览以及同步模式 current 指针的独立检查仍存在，不能把这个数字当作整次 API 调用的全部清单读取量。AI 清单约 23.75 MB，少提交约 47.5 MB 的逻辑清单读取并避免两次完整 JSON 解码。
- 元数据读取已知道普通文件大小，改为按大小一次分配缓冲区，额外读 1 字节检测增长，避免大清单在 `io.ReadAll` 扩容时反复分配/复制。保留大小上限、普通文件检查、O_NOFOLLOW/O_NONBLOCK、短读/增长拒绝及读取前后物理版本检查。

## 其余链路结论

- 手动与后台预览使用 Go 索引扫描和固定小样本 rsync 能力探测，不把真实源目录清单交给 rsync。投影/指纹仍要求身份、策略、版本及完整性验证，失效会完整扫描。正式执行保留新鲜扫描和单次批准绑定，不能沿用过期预览直接写入。
- 零变更正式执行：历史副本和源分别完整哈希一次；结束全目录扫描只复用本次已经完整读取的源哈希，APFS 稳定版本无需再次读内容。源与备份副本不能互相替代，也不跨运行缓存完整审计结果。
- 有变更：新一代之前的完整 rsync 预演、同步模式历史审计、候选硬链接复用时的独立源/历史检查、完成后的暂存完整验证仍保留。这些跨写入阶段的验证保证不同时间的状态，并非相邻的同一份结果解析。此次没有引入跳过最终暂存读取的缓存；直接复用会改变硬链接计数/ctime，简单复用旧哈希可能掩盖期间篡改。
- 真实传输只提交剩余清单，复用文件不进入 rsync，不使用历史 link-dest；不会让 rsync 更新共享历史 inode。零变更无暂存/manifest/receipt/current 写入。
- 新一代仍 fsync 文件/目录并原子发布，不能把操作系统缓存中的完成当成可持久化完成。零变更不会走这条 fsync 链路。
- 内容读取保持串行，避免机械备份盘并发随机小文件读取增加寻道和队列；此前源目录并发预取实验更慢，未加入默认配置。本轮没有清缓存、触发全盘同步或扩大读取范围来制造数字。
- 已有列表摘要查询、隐藏页面暂停轮询、请求不重叠、磁盘身份信息限频、监控锁外编码仍在。文件读取进度只更新内存监控，不逐文件写 SQLite；任务审计按阶段保留。

## 验证

`go test -race ./...`、`go vet ./...`、前端/Go 构建和应用签名验证。新增检查覆盖目录记录零行写入与零 WAL、真实差异增删改、禁用范围保持、空选择、非法范围/重复路径、取消/失败回滚、清单校验期间被篡改，以及空/精确上限/大元数据读取。现有完整源/历史读取次数、结束扫描、三种模式、复用历史不变、批准和混合目标回归仍执行。

隔离目录记录基准，Apple M3 Max，38,356 条合成记录、相同 SQLite 设置，单次同批规模对比：删除/插回 371.558 ms，WAL 11,927,432 B；差异同步 101.960 ms，WAL 0 B。该基准测的是目录记录事务，不能冒充实际 AI 计划全程耗时或全应用总写入。

## 本机应用验收

原生应用已更新并验证签名为 0.21.11。原 AI 模型计划升级前观测 31.938 秒（实际执行 31.612 秒），升级后无排队受控观测 23.331 秒（实际执行 22.839 秒）。使用 macOS proc_pid_rusage 对服务进程计数，前后均含 10 秒收尾：磁盘写入 74,842,112 B -> 999,424 B；备份物理盘两次均 0 B 写入。新版备份盘读取 690,929,664 B，旧版 1,419,939,840 B，受内核缓存影响，不将该读取差额当作代码消除的逻辑读取量。

新版仍各完整读取源/历史副本 38,356 个普通文件、1,326,773,331 B，结束复核额外内容读取 0 B；42,302 条目录记录无增删改。另两轮实际执行 27.018/24.619 秒；首轮混入启动自动任务，第二轮计量脚本时间解析修复导致收尾延长，二者只验证执行结果，不用于前后 IO 比较。未为测量修改真实源文件，未创建测试计划。两份计划和五份历史恢复点逐条保持原值，AI 恢复点仍为三份。

证据：`.data/performance-0.21.11-acceptance.json`、其中引用的原始计量、`.data/performance-0.21.11-preservation.json`、`.data/performance-0.21.11-tests.log`、`.data/performance-0.21.11-vet.log`、`.data/performance-0.21.11-build.log` 和目录事务基准日志。回退应用及一致数据库位置保存在 `.data/performance-rollback-location.txt`。
