# 0.21.1 性能检查与优化

2026-10-22，本机 Apple M3 Max。

## 已处理

- 历史快照列表直接从 SQLite 提取摘要，避免 Go 为全部文件清单分配对象；按计划过滤在查询中完成，仍按实际时间排序。
- 预览/执行查找基线时只解码选中的最新快照完整清单，不解码所有历史版本；数据库错误向上传递，不能作为“无历史”继续。
- 前端运行记录采用摘要请求，不传输逐文件 operations/removals；完整 API 和操作详情保持可用，统计、日志保留。
- 页面隐藏时暂停客户端轮询，返回可见立即刷新；请求未完成时不叠加下一次请求。后台备份和监控采样继续执行。
- 卷发现周期从 3 秒改为 30 秒，任务进度保持原刷新周期。代价是页面磁盘列表最多约 30 秒更新；实际执行仍校验磁盘身份。
- 磁盘监控输出先复制采样列表，再释放锁后编码和发送；慢客户端不再占住采样锁。
- diskutil 元数据查询失败后等待 60 秒重试，避免睡眠/异常设备每秒启动一次探测。实时读写计数仍每秒采样，未知设备位置保持 unknown。

## 可复现测量

`go test ./internal/store -run TestSummary -bench BenchmarkSnapshotList -benchmem -count=1`

隔离临时数据库，5 个快照，每个 10,000 条文件记录；不读取个人备份内容。

| 查询 | 耗时/次 | Go 分配/次 | 分配次数/次 |
| --- | ---: | ---: | ---: |
| 原完整解码 | 70.27 ms | 61,581,140 B | 150,181 |
| 摘要查询 | 24.05 ms | 12,112 B | 72 |

查询耗时约减少 66%，Go 分配量约减少 99.98%。SQLite 仍需解析存储的 JSON；数据规模继续增长时应考虑独立摘要列/表及分页。这不是文件扫描速度或整个应用峰值内存的测量。

## 验证及剩余问题

- 全套 Go race 测试、go vet、TypeScript、前端构建；新增摘要排序/过滤/完整数据保留、最新基线读取测试。
- 轮询测试覆盖慢请求不重叠、隐藏页面不请求、重新可见立即刷新、卸载后停止。
- SHA-256、属性检查、路径/卷身份验证和发布前校验保持原有要求。
- 用户已开启 LocalBackup 完全磁盘访问。重新启动后照片扫描依然阻塞于目录 open，0 paths/bytes；用户确认此次没有访问提示。这是尚未解决的独立问题，不能把以上基准当作该扫描已经恢复。
- 本轮没有执行用户数据备份、恢复或保留清理。
