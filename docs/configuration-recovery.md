# 从备份盘恢复配置与历史（0.15.0）

新快照的不可变 manifest 保存完整计划配置，包括所有源、全部目标绑定、规则与文件条件、调度、保留策略和原物理源身份。单目录或轮换目标运行也保存完整计划，而不是当次裁剪后的执行配置。运行审批、队列、事件游标和实时缓存信任不写入这些配置。

永久保留标记独立保存于 `LocalBackup/metadata/pins/<snapshotId>.json`，绑定仓库、计划和快照 ID。更新使用仓库锁、临时文件、原子改名和目录同步，不修改任何已提交快照。只有磁盘更新成功后才更新本地标记；目标离线时操作明确失败。数据库写入失败可能留下更保守的磁盘标记，导入不会解除本地已有的保护。

在设置中选择“从备份盘恢复配置与历史”：选择包含 LocalBackup 仓库的目标目录，系统校验完整文件内容、布局和启用的扩展属性，再列出可恢复计划、恢复点数量、保留数量与冲突说明。可以取消，或只恢复历史。确认后重新校验磁盘与本地版本；预览有效期十分钟、只可使用一次，进程重启后失效。

恢复将计划、历史、历史文件索引、保留状态及审计记录放在一个 SQLite 事务中。计划始终暂停；保留旧绑定，离线源不被重新绑定到替代目录。已有同 ID 计划不覆盖，跨计划源 ID/源目标路径冲突不导入配置，已有快照清单不一致时拒绝提交。源位于服务数据目录的配置不会导入。运行中的文件任务会阻止恢复，恢复期间其他文件任务等待。

同一计划从所选仓库最近一份含完整配置的快照恢复；其他尚未连接磁盘上可能存在更新配置，恢复前应核对预览。旧版本清单没有完整配置时只恢复历史，不猜测规则与任务。磁盘永久保留标记缺失、损坏或被链接替代时，相关恢复点按永久保留导入并明确提示；可以连接磁盘后逐个确认解除。不会因为标记不可靠而降低保护。

`file_entries` 是从历史清单重建的备份文件视图。当前源可能已变化，因此 `source_paths`、物理内容缓存、原生事件游标和调度检查点不从旧清单直接信任：检查源与目标后执行“完整重扫源文件”，重新读取实际源内容，创建新的索引与缓存。此重扫也不会触发自动备份。全新数据库验收覆盖了这一流程。

这恢复的是最近成功快照所记载的计划和历史，不是所有本机数据库内容的备份：上次成功备份后未运行的计划修改、未落盘的旧版永久保留标记、旧运行/恢复审计、执行中的队列和设备设置无法从旧快照推导。旧数据目录应先保留或改名；程序不会自动删除或修复损坏 SQLite。

元数据读取要求普通文件，不跟随链接或读取设备/FIFO。仓库标识最大 64 KiB、单份保留标记最大 4 KiB、单份快照清单最大 1 GiB；规模和内存占用仍需大数据验收。恢复预览与确认都执行完整校验，大仓库可能耗时较长。
